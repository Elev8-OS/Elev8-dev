### Channels (`/channels`)

Connect OTA accounts, then choose which listings each OTA sells. Mock only: connecting an account or a listing is a timer, not a channel manager call.

#### Pages (NextPax redesign, phase 1 of `docs/claude/nextpax-channels.md` "Simplified flow")
- **`/channels`** (`pages/channels/index.vue`): one sentence on coverage, "Needs a look" (every listing in Error or Needs attention, linking to its channel page), "Your channels" (one row per connected channel with status counts, plus the Website row), "Add a channel" (cards with the channel's sign-in kind; "Continue" once a wizard was started). The Website channel keeps its own sheet.
- **`/channels/<slug>`** (`pages/channels/[slug]/index.vue`, `ChannelManage.vue`): the slug is `channelSlug(name)` (`booking-com`), never the NextPax code. Status tiles (Error, Needs attention, Syncing, Live) that filter the table, search, then one row per listing on the channel: status + the channel's own message, its channel id (links to the OTA page), account when there are several, last sync, and a menu (Sync again, Unlink when the channel links ids, Take off). Header: Add listings (wizard at Listings), Account and sign-in, Policy and payments, Turn off.
- **`/channels/<slug>/connect`** (`pages/channels/[slug]/connect.vue`, `ChannelConnectWizard.vue`): one wizard for every channel, `?step=` in the URL. A step opens only when the ones before are done; Continue names what is missing.
  1. `ChannelStepAccount`: form generated from the setting definitions, then sign-in by `spec.signIn`: `settings` (nothing more), `link` (Airbnb: paste the link Elev8 sent, "Sign in with Airbnb" + age, stale after 14 days), `sso` (Vrbo: advertiser id, get link, "I have signed in", match existing properties switch = `confirmMappingOfPropertyIds`).
  2. `ChannelStepReadiness`: cancellation policy for this channel (presets, picked in place) and payment methods (Booking.com, shared by every channel). The photo minimum is a warning in step 3, never a gate.
  3. `ChannelStepListings`: per listing not on the channel: New / Link / Skip (default New), Link asks the channel's ids (`spec.linkIds`) and offers "copy content from the channel"; on Booking.com it also pairs each Elev8 rate plan with the Booking.com rate plan id it already has (`ratePlanPairs()` builds `channel_rate_plans`, empty = a new plan on the channel; rate plans are the listing's own that sell on Booking.com, `channelRatePlans()`). A linked listing with a pair is spared the mock rate plan warning; settings with `availableOnPropertyLevel` (legal entity, pricing model) can be set per row, empty = account value. Photo shortfall flagged per row.
  4. `ChannelStepConnect`: review, connect, then each listing with its live status (Syncing to Live, or Needs attention with the warning).
- `ChannelStatusBadge.vue`: the five states (Live, Syncing, Needs attention, Error, Not connected) from `MAPPING_STATUS_LABEL` / `_ICON` / `_TONE` / `_DOT` in `data/channels.ts`. Listings cells, Cockpit links and the mapping dialog read the same maps.

#### Pricing for channels (phase 3, in the listing's Pricing tab, not `/revenue`)
`/revenue` is Listing Health, a separate feature: none of this lives there.
- **Rate plans** (`ListingPricingTab` sheets, `RatePlanChannelsField.vue`): `RatePlan.channels` (NextPax `applicableChannels`, empty = every channel) and `RatePlan.code` (`RP0001`, given on save by `nextRatePlanCode` across every listing; older plans fall back to their id). The rate plan card shows the channels and code. **A channel's own cancellation policy** is a plan that sells only there with its own policy (the rate plan's existing inherit/override policy). The wizard's Readiness policy stays: NextPax still needs one channel-specific policy per account.
- **Channel promotions** (`ListingChannelPricing.vue`, `Listing.channelPromotions`): early bird / last minute / basic, percent or amount (listing currency code), off the rent or the total, days before arrival, stay dates, min/max nights, channels (`PROMOTION_CHANNELS`: Airbnb, Booking.com, Expedia, Vrbo), active switch. Validation `promotionIssues`. Promo Codes (codes guests type) stay separate.
- **Channel price adjustments** (same component, `Listing.channelAdjustments`): rate % and fee % per connected channel (NextPax rate and fee multipliers), saved on change, -100 < % <= 500, with the price a base night becomes.
- **Copy to listings** (`ChannelCopyToListingsDialog.vue`, `PropertyPicker`): promotions (fresh ids) or adjustments replace the picked listings' at once.
- **Currency conversion** (`useChannelFeatures().currencyFx`, "For every channel" on `/channels`): NextPax converts what it sends into a channel's currency. The one decided exception to "no currency conversion" (CLAUDE.md); Elev8 never stores or shows a converted amount.
- Rules in `data/channel-pricing.ts` (pure, `tests/lib/channel-pricing.spec.ts`), UI spec `tests/components/channels/ListingChannelPricing.spec.ts`.

#### Rules
- **Many accounts per channel** stay in the model: `ChannelMapping.accountId`, a listing is on a channel through at most one account. The UI shows the account name and an Account column when a channel has several; the wizard connects through the first account (the per-listing overrides in step 3 are what "another account" means for NextPax). "Move to account" is only in `ChannelMappingDialog`.
- `propertyId` is unique per channel (`isPropertyIdTaken()`).
- **Needs attention is not Live**: a listing the channel accepted with a warning is not selling. It is cleared by a resync, like an error.
- **One writer**: `useChannels` is the only writer of `Listing.otaConnected`, in `CHANNELS` order. Channel names are the stored strings (`'Airbnb'`, `'Booking.com'`, `'Vrbo'`); do not rename them.
- Seeding: accounts for every channel some listing uses (`Elev8 Suite DACH` listings on a second Airbnb and Booking.com account), mappings `active`; the first Booking.com mapping is `error`, the second `attention`.
- Mappings start `syncing` and go `active` after `CHANNEL_SYNC_DELAY_MS`.
- OTA logos: always `otaIcon(name)`. Vrbo and Agoda use `lucide:house` / `lucide:hotel`.
- ⚠️ Real channels map **room types**; mapping is still per listing here.

#### Website channel
Direct bookings on the tenant's own websites (Website Builder) and booking widgets. It has no OTA account, so it is **not** in `CHANNELS`, never writes `Listing.otaConnected` and gets no OTA column (the Listings table has its own "Website" column, see `docs/claude/listings.md`).
- **Rule sets, assigned to websites, not listings.** The channel holds rule sets the way an OTA holds accounts. Each has a name, `websiteIds` and its settings: length of stay tiers, early bird / last minute, min/max stay, booking notice, arrival/departure weekdays, prepayment %. Listings come from the website itself (`getListingIdsForWebsite`), never stored here; a site with no `propertyIds` shows "Listing coverage not set".
- **One website, one rule set, no Default.** A rule set needs a unique name and at least one website. `upsertRuleSet` moves a site out of any other set on save. A site in no rule set (`unassignedWebsiteIds`, `ruleSetForWebsite` returns undefined) takes direct bookings without Website discounts or rules; the sheet list names those sites. Deleting a set leaves its sites in none.
- **Promo codes are not part of a rule set.** Promo Codes owns where a code works (`channelRestriction`); the editor only lists the codes valid on its sites (`isPromoCodeValidOnWebsite` in `promo-codes.ts`) with a link to Promo Codes. Older saves with `promoCodeIds` are cleaned by `parseWebsiteState`.
- `data/website-channel.ts`: types, `WEBSITE_CHANNEL`, module-level ref `websiteChannel` (`{ enabled, ruleSets }`, read outside setup by the widget preview builder), `ruleSetIssues()`, `ruleSetSummary()`, `parseWebsiteState()`. Imports nothing from Website Builder.
- `useWebsiteChannel()` is the only writer: `saveRuleSet()` (returns issues, saves nothing when there are any; **saving the first rule set is what adds the channel**), `deleteRuleSet()`, `assignWebsite(websiteId, ruleSetId | null)` (Website Builder, one site at a time), `disable()` (keeps rule sets), `enable()` (re-add). Saved to localStorage (`elev8-website-channel`); every page that reads it calls `hydrate()` in `onMounted` so SSR and the first client render match.
- UI: the Website row under "Your channels" on `/channels` (or its card under "Add a channel"). Adding opens `WebsiteChannelSheet` with `start="new"`: name + pick websites + settings, button "Add channel"; cancelling adds nothing. The card's "Manage rule sets" opens the list. Editor `WebsiteRuleSetForm` works on a draft, saved only on Save, and ends with `WebsitePriceCheck`.
- Rules: discounts are **percent only** (listings sell in different currencies). Last minute must end before early bird starts.

#### Website price (`data/website-quote.ts`, `useWebsiteQuote`)
- `websiteQuote(input)` is pure; `useWebsiteQuote().quoteStay({ listingId, checkIn, checkOut, bookedOn, ruleSet })` feeds it: nightly prices from the room's revenue policy (`previewPolicy` from the booking day, so policy last-minute rules see the real lead time), the unit type's `lengthOfStayDiscounts` and the policy's weekly / monthly %. A listing with units is priced on its first room.
- **Which discount wins.** With a rule set, its highest tier reached **replaces** the listing tiers and the policy weekly / monthly %; early bird **or** last minute is added; every discount is off the stay subtotal. Without a rule set, the single biggest of the listing tiers and the policy weekly / monthly % (never stacked).
- Rounded per currency, no conversion. `blockers` lists the stay rules a stay breaks; `prepayment` is the rule set's % of the total.

#### Booking widgets
- `BookingWidgetConfig.websiteRuleSetId` (null = the widget's own). `resolveWidgetBookingRules()` (used by `buildEmbedPreview`) returns the rule set's tiers, early bird / last minute, min/max stay, booking notice, arrival/departure days and prepayment wholesale, while the channel is added and the set exists; otherwise the widget's own. Seasonal arrival rules stay the widget's and narrow the rule set's days.
- `WidgetRuleSetSelect` ("Booking rules") is shared by the v1 editor (top of Pricing & Fees; prepayment, booking notice and stay discounts then read from the set) and v2 (own card, "No discounts or stay rules" when none). It says so when a picked set was deleted. The preview's sidebar names the source.

#### Elsewhere
- Website Builder has no rule set picker: its Settings step (section "Site Settings" in the edit layout) (in the edit layout, section "Site Settings") holds this site's own rules inline (`WebsiteRuleSetForm` with `siteOnly`: length of stay tiers, early bird / last minute, stay rules, prepayment; no name, website list, promo list or price check). On publish `useWebsiteChannel().saveSiteRules(websiteId, siteName, rules)` saves them: a set only this site uses is updated in place, a shared set is left to the others and the site gets its own set named after the site. `assignWebsite` is no longer used by the wizard, Listings show which websites sell a listing, reservations keep a frozen `websiteBooking` snapshot, Analytics splits Direct by website. See those module docs.
- Revenue → Channel markups keeps one "Direct" row for every website. No markup per rule set yet: the rule set's discounts already cover website pricing.
