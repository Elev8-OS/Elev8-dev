# Website Builder

- `/website-builder/create` (create and `?edit=`) uses `layouts/builder.vue`: full screen, no sidebar and no app header, Back returns to `/website-builder`. It follows the mobile onboarding order: Guests, Tone (one tap moves on, "Skip" allowed), Languages (multi-select, star = default, formal/informal only for DE/FR/ES/IT/NL, auto-detect), a 1.8s "Let's set up your website" transition, Style (preset, primary color, font pairing), Listings (`PropertyStep` embedded, at least one property), Details, Final review, Generating, Preview (`PreviewStep`, Save draft / Publish). The progress bar covers the 7 interactive steps; Back skips the transition. Orchestrator state is `step: StepKey` in `create.vue`; step components live in `components/website-builder/wizard/` and the shared lists, `WizardAnswers` and address checks in `data/wizard.ts`. With `?edit=<id>` it renders `WebsiteEditor.vue` instead.
- **Details** (`wizard/DetailsStep.vue`): title, address (`<slug>.elev8-stays.com` or own domain, must pass the mock "Check" before Next; the slug follows the title until edited), logo/favicon (file names only), contact, then collapsible Reviews (`ReviewStep` embedded), SEO (60/160 limits), Legal, Booking rules (`WebsiteRuleSetForm`, still saved through `saveSiteRules`). Contact, SEO and Legal answers are kept in `WizardAnswers` only: the Website model has no fields for them yet. Hero Media, analytics tracking IDs and custom head/body HTML from the mobile flow are not built.
- The old Template step is gone: the Style preset picks the saved template name (`STYLE_PRESETS[].template`: minimal = Minimal Bali, warm = Beach House, bold = Luxury Villa, airy = Modern Tropical). `create.vue` folds the address and font pairing into `finalSettings` before Final review, Preview and save. Generating is a timer over `GENERATION_STAGES`, nothing is sent anywhere. Guests, Tone, languages and formality are collected but not stored on the Website (the mock engine does not use them).
- **Edit layout** (`components/website-builder/WebsiteEditor.vue`): header (name, listing count, status icon, URL, Re-render, Unpublish, Save changes / Publish), left section nav, one section at a time. AI Generate (default) is a chat (`WebsiteAiChat.vue`: greeting + suggestion chips, thread, composer, built on the `ui/message`, `ui/conversation` and `ui/prompt-input` primitives) beside a live `WebsitePreviewFrame.vue`, split by a draggable `ResizablePanelGroup` (chat 25-75%, size remembered per orientation via `auto-save-id`; stacked vertically below `lg`). Mock engine: it only changes the headline (`settings.description`), brand color and font, and says so for anything else; nothing is sent anywhere. Site Settings is `WebsiteSiteSettings.vue`, laid out like the v2 dashboard: Identity (title, logo, favicon with preview and Reset), Address (platform subdomain with a move warning, custom domain with a Pending/Active chip and the CNAME records for it and its www/apex twin), Save changes and a re-render prompt after a save. A site stores one address: `*.elev8-stays.com` is read as the subdomain, any other address as the custom domain, and the custom domain wins on save. Saving after a subdomain change re-renders automatically. Brand color, font and headline are no longer fields here, only AI Generate changes them. Booking Rules is its own menu entry under Site Settings (`WebsiteBookingRules.vue`: `WebsiteRuleSetForm`, saved via `saveSiteRules`, Save changes). Manage Listings and Reviews embed `PropertyStep` and `ReviewStep` with `embedded` (no Back / Next). `steps/SettingsStep.vue` is now only the home of the `WebsiteSettings` type. The chat header has a History popover (no separate Version History section): the current version plus one entry per ElevAI change this session, each restorable; the chat stays mounted (`v-show`) while another section is open. Analytics reads the website record; Hero Media, Blog, Surroundings, SEO and Cookie & Legal are empty states for now.
- Saving goes through `useWebsiteSave().saveWebsite()`, shared with `PreviewStep`. It writes the Website and hands the site's booking rules to `useWebsiteChannel().saveSiteRules()` (see `channels.md`). A website stores `propertyIds`, not rooms, so the editor only requires one property.
- The editor does not run the Reviews step's own validity check; it saves the selection as it stands.
