# Website Builder

- `/website-builder/create` (create and `?edit=`) uses `layouts/builder.vue`: full screen, no sidebar and no app header, Back returns to `/website-builder`. It follows the mobile onboarding order: Guests, Tone (one tap moves on, "Skip" allowed), Languages (multi-select, star = default, formal/informal only for DE/FR/ES/IT/NL, auto-detect), a 1.8s "Let's set up your website" transition, Style (preset, primary color, font pairing), Listings (`ListingsStep`, at least one listing), Details, Final review, Generating, Preview (`PreviewStep`, Save draft / Publish). The progress bar covers the 7 interactive steps; Back skips the transition. Orchestrator state is `step: StepKey` in `create.vue`; step components live in `components/website-builder/wizard/` and the shared lists, `WizardAnswers` and address checks in `data/wizard.ts`. With `?edit=<id>` it renders `WebsiteEditor.vue` instead.
- **Details** (`wizard/DetailsStep.vue`): title, address (`<slug>.elev8-stays.com` or own domain, must pass the mock "Check" before Next; the slug follows the title until edited), logo/favicon (file names only), contact, then collapsible Reviews (`ReviewStep` embedded), SEO (60/160 limits), Legal, Booking rules (`WebsiteRuleSetForm`, still saved through `saveSiteRules`). Contact, SEO and Legal answers are kept in `WizardAnswers` only: the Website model has no fields for them yet. analytics tracking IDs and custom head/body HTML from the mobile flow are not built.
- The old Template step is gone: the Style preset picks the saved template name (`STYLE_PRESETS[].template`: minimal = Minimal Bali, warm = Beach House, bold = Luxury Villa, airy = Modern Tropical). `create.vue` folds the address and font pairing into `finalSettings` before Final review, Preview and save. Generating is a timer over `GENERATION_STAGES`, nothing is sent anywhere. Guests, Tone, languages and formality are collected but not stored on the Website (the mock engine does not use them).
- **Edit layout** (`components/website-builder/WebsiteEditor.vue`): header (name, listing count, status icon, URL, Re-render, Unpublish, Save changes / Publish), left section nav, one section at a time. AI Generate (default) is a chat (`WebsiteAiChat.vue`: greeting + suggestion chips, thread, composer, built on the `ui/message`, `ui/conversation` and `ui/prompt-input` primitives) beside a live `WebsitePreviewFrame.vue`, split by a draggable `ResizablePanelGroup` (chat 25-75%, size remembered per orientation via `auto-save-id`; stacked vertically below `lg`). Mock engine: it only changes the headline (`settings.description`), brand color and font, and says so for anything else; nothing is sent anywhere. Site Settings is `WebsiteSiteSettings.vue`, laid out like the v2 dashboard: Identity (title, logo, favicon with preview and Reset), Hero media (display mode Static / Carousel / Video; draggable photos, the first is the hero in Static; video upload; stored on `WebsiteSettings.heroMode`, `heroImages` as local previews and `heroVideoFile`, nothing is uploaded), Address (platform subdomain with a move warning, custom domain with a Pending/Active chip and the CNAME records for it and its www/apex twin), Save changes and a re-render prompt after a save. A site stores one address: `*.elev8-stays.com` is read as the subdomain, any other address as the custom domain, and the custom domain wins on save. Saving after a subdomain change re-renders automatically. Brand color, font and headline are no longer fields here, only AI Generate changes them. Booking Rules is its own menu entry under Site Settings (`WebsiteBookingRules.vue`: `WebsiteRuleSetForm`, saved via `saveSiteRules`, Save changes). Manage Listings is `steps/ListingsStep.vue` around `shared/ListingRoomPicker.vue`, the same picker as the create wizard: a tree of the real Listings (listing > room type > room, tri-state boxes, search, Select all / Clear; a single-unit listing is just a row). `PropertySelection` (`data/property-listings.ts`) holds `propertyIds` = **listing ids** and `roomIds` = unit ids; a website still saves only `propertyIds`, so opening one ticks every room of its listings (`selectionForListings`). ⚠️ Old sites saved legacy `prop-N` ids: `getListingsForProperties` maps them through `propertyListingMap` and passes real listing ids through, so both work. Manage Listings and Reviews each end with a Save changes button. Reviews embeds `ReviewStep` with `embedded` (no Back / Next). Rule labels (stay rules, arrival and departure days, prepayment) carry an info tooltip (`channels/WebsiteRuleHint.vue`); `layouts/builder.vue` provides the `TooltipProvider`. `steps/SettingsStep.vue` is now only the home of the `WebsiteSettings` type. The chat header has a History popover (no separate Version History section): the current version plus one entry per ElevAI change this session, each restorable; the chat stays mounted (`v-show`) while another section is open. Analytics reads the website record; Surroundings, SEO and Cookie & Legal are empty states (Hero Media has no menu entry, it lives in Site Settings) for now.
- Saving goes through `useWebsiteSave().saveWebsite()`, shared with `PreviewStep`. It writes the Website and hands the site's booking rules to `useWebsiteChannel().saveSiteRules()` (see `channels.md`). A website stores `propertyIds`, not rooms, so the editor only requires one property.
- The editor does not run the Reviews step's own validity check; it saves the selection as it stands.
- **Languages** (Site Settings): add or remove site languages (`WebsiteSettings.languages`, `defaultLanguage`, `autoDetectLanguage`, saved on the Website; the create wizard's Languages answers seed them, an old site reads as English only). The last language cannot be removed, removing the default moves it to the first left. ⚠️ `saveWebsite` spreads these fields over the stored site, so `create.vue` must prefill them when editing or a save would wipe them.
- **Blog** (`WebsiteBlog.vue`, data in `data/blog.ts`): posts live on the Website (`blogPosts`). A post has one `translations[code]` (title, summary, post) per site language, `status` draft or published (publishing needs the default language written), `topic`, `aiGenerated`. List cards show the cover thumbnail, status, AI badge, one chip per language (filled = written, dashed = missing) and a **Publish / Unpublish** button (disabled with a hint while the default language is not written; saves the website). **Generate with ElevAI** asks for a topic and drafts the post in every site language, and a cover picture, then opens the editor. The editor starts with the **cover picture** (`BlogPost.cover`, a data URL): Generate with AI / Generate again (`generateCover(topic, seed)`, a landscape SVG whose colors come from the topic and seed, mock), Upload (read to a data URL) or Remove. Then one tab per language, "Write with AI" or "Rewrite with AI" per language and "Write all missing". ⚠️ Mock engine: `draftTranslation(topic, siteName, code)` fills a fixed template per language (en, de, fr, it, es, nl, id, zh) from the post's topic, so "translate" writes a fresh draft from the topic, not a translation of edited text. Saving, publishing or deleting a post saves the website (`save` emit, after `nextTick` so the parent already has the new posts).
