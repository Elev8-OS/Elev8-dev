- Place all `<script setup>` imports at the top of the block — never interleave `import` statements with reactive state declarations or function definitions. Confidence: 0.85

- When props are only used in the template, declare `defineProps<{...}>()` without assigning it to a variable: `const props = defineProps(...)` trips the unused-vars lint rule, but removing the call entirely breaks template type inference — the bare call is the clean middle ground. Confidence: 0.75
- When a shadcn-vue `Select`'s `@update:model-value` handler signature conflicts with `AcceptableValue`, either cast the callback inline (`@update:model-value="(v: any) => ..."`) or widen the declared handler's parameter to `unknown` and cast inside the function — both pass typecheck + lint (widening to a specific type like `string` still fails; the editable-status handler was fixed by widening to `unknown`). Confidence: 0.8
- Place `defineProps` before `defineEmits` in `<script setup>` blocks (ESLint enforces this macro ordering — props first, then emits, both right after imports). Confidence: 0.85
- Remove unused helper functions before committing; ESLint `no-unused-vars` will fail CI lint and block PR merge if a declared function is left without a call site. Confidence: 0.82
- When seed/fixture data needs to represent an edge case that violates the production type (e.g. a non-conforming VAT rate for a `needs_mapping` invoice), widen the production type to `number` rather than casting at the seed site — keeps the type honest about what the model can carry while still validating the constraint at the pipeline boundary. Confidence: 0.80
- Reka UI Calendar `v-model` bound to a transforming computed (getter/setter that converts a `CalendarDate` to a string) does not reliably commit a date selection, especially for a Popover nested inside a Sheet; instead bind a plain `ref<CalendarDate | null>` with `:model-value` + `@update:model-value="commitDate"` (emit `val.toString()`) and a `watch` syncing back from the string prop. The same computed-based pattern works fine in a Dialog context, so verify in the actual Sheet context. Confidence: 0.65
- When the same composable is called in multiple components and its state must be shared (e.g. analytics filters consumed by both a filter bar and the KPI/chart components on one page; review-hub sort consumed by both the page and `FeedTable`), back the refs with `useState(sharedKey, ...)` instead of plain `ref` — plain refs create a fresh instance per call site, so a control toggled in one component silently diverges everywhere else (user: "ngga berfungsi sortnya" — the sort header toggled its own state but `filteredFeedItems` was computed from the page's separate instance). Fix by converting the refs to `useState` with shared keys, matching the repo's existing pattern. Confidence: 0.85

- Reka UI ScrollArea inside a flex-column SheetContent does NOT scroll with `flex-1` alone — the ScrollAreaViewport needs a bounded height to scroll. The canonical fix: `h-full min-h-0` on the ScrollArea (allows the flex child to shrink below content height) plus `overflow-hidden` on the SheetContent. The user reported "i cannot scroll on the sheet" and verified the fix after it was applied. Confidence: 0.8

Confidence: 0.65
